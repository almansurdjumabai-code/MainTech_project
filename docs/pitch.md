# Питч CQA: сценарий защиты на 5 минут

План из гайда организаторов: 1 мин интерфейс → 2 мин оценка, переход к реплике, N/A, итог → 1 мин апелляция → 1 мин замена критерия. Все цифры ниже — фактические, с прогона DEV 2026-11-08.

## Роли
- **Спикер** говорит и смотрит на жюри, не на экран.
- **Пилот** кликает молча, на шаг впереди спикера. Пилот знает этот документ наизусть.

## За 15 минут до выхода
1. Двойной клик по **`start.bat`** в корне репозитория → откроется http://127.0.0.1:8000/. Если сервер уже работает, скрипт просто откроет браузер.
2. Проверить http://127.0.0.1:8000/health: `"judge":"openai_compat"` (Gemini подключён). Если там `rules`, демо всё равно работает, только на правилах.
3. Открыть заранее вкладки: **Дашборд**, карточку `p1-ru-013`, карточку `p1-ru-025`, **Чек-листы**.
4. Проверить, что у `p1-ru-025` нет открытой апелляции: её подаём вживую.
5. Масштаб браузера 110–125%, уведомления Windows выключить, звук на ноутбуке включить (звонок).
6. **Лимит бесплатного Gemini:** 500 запросов в сутки на модель, сброс около 13:00 по Астане. Когда основная модель (`gemini-flash-lite-latest`) исчерпала лимит, система сама переходит на запасную `gemini-3.8-flash`: она точная, но медленная, около 100 с на диалог. Уже оценённые диалоги открываются мгновенно, ответы модели берутся из кэша. Для живой переоценки на сцене выбирать в UI «Правила без LLM»: это займёт секунду.
7. **Запасной вариант:** видео прохода по этому сценарию на рабочем столе. Если пропал интернет, оценка сама переходит на правила, а данные уже лежат в локальной базе.

## Сценарий

### 0:00–1:00 · Проблема и интерфейс
**Пилот:** вкладка **Диалоги**, видна таблица 65 диалогов (RU/KZ/EN, чаты и звонки).

**Спикер:**
> «Сейчас QA вручную слушает звонки и читает чаты, проверяет выборочно и долго. Мы сделали CQA: система оценивает каждый диалог по чек-листу из PDF, и **каждый балл подтверждён репликой**, на которую можно кликнуть. Перед вами все 65 диалогов DEV на трёх языках, 60 чатов и 5 реальных звонков, все уже оценены».

**Пилот:** **Дашборд** → показать правую панель.
> «Оценка 65 диалогов стоила **$0**: бесплатный Gemini плюс наши правила. Это фактические цифры из backend, а не оценка».

### 1:00–3:00 · Оценка, доказательство, N/A, итог
**Пилот:** карточка **`p1-ru-013`** (итог 100).
> «Восемь критериев. У каждого есть ответ, баллы, вес и объяснение. Кликаю на доказательство…»

**Пилот:** клик по реплике в критерии «Установление контакта» → транскрипт прокручивается и подсвечивает реплику.
> «…и попадаем ровно на реплику оператора. Здесь два **N/A**: выявление потребности и идентификация. Причина написана, а их вес **перераспределён** между остальными критериями, поэтому итог 100, а не 65. Расчёт итога раскрывается по шагам».

**Пилот:** раскрыть «Как посчитан итог».

**Пилот:** карточка **`p4-ru-001`** (звонок) → клик по доказательству → плеер перематывает запись.
> «У звонков клик по реплике перематывает запись на этот момент».

**Пилот:** карточка **`p1-kz-013`** (казахский чат).
> «Казахский оцениваем **в оригинале, без перевода**. Итог высокий, 92.31, но стоит **флаг грубой ошибки**: оператор предложил частную платную консультацию. По чек-листу флаг ставится отдельно и баллы не обнуляет. Интересная деталь: Gemini отказался анализировать этот диалог своим фильтром безопасности, а наш второй контур, правила, нарушение поймал. Поэтому у нас два метода, а не один».

### 3:00–4:00 · Апелляция и решение
**Пилот:** карточка **`p1-ru-025`**, итог **53.33**. Критерий «Корректная консультация» = 0.
> «Клиент ушёл до того, как сформулировал вопрос. По чек-листу здесь N/A, а модель поставила 0. Оспорим».

**Пилот:** роль **QA** → «Оспорить» → комментарий «Клиент ушёл до запроса — по чек-листу N/A» → «Подать апелляцию».
**Пилот:** роль **Проверяющий** → **Апелляции** → открыть → видны спорная оценка, комментарий и фрагмент диалога → «Изменить оценку» → **N/A** → причина «Запрос не был сформулирован» → сохранить.
> «Итог пересчитан: было **53.33**, стало **72.73**. В карточке видны исходная оценка AI, решение проверяющего с причиной и финальный итог. Всё сохранено в базе и переживает перезагрузку».

### 4:00–5:00 · Замена критерия без кода
**Пилот:** **Чек-листы** → критерий «Управление диалогом» → поменять название и описание, например «Оператор предложил мобильное приложение», тип «Да/Нет» → «Сохранить как новую версию» с галочкой **«Сразу сделать активной»** → «Переоценить» 2–3 диалога. Если Gemini в этот момент медленный, в переключателе модели выбрать «Правила без LLM»: это займёт секунду, но новый критерий без ключевых слов правила честно отправят на проверку.
> «Организаторы меняют критерий, мы меняем его в интерфейсе. Создаётся **новая версия** чек-листа, старые оценки остаются в истории. Новый критерий оценивает модель по его формулировке, **код не меняется**. Одна оценка занимает около 7–12 секунд».

**Финальная фраза (10 с):**
> «Итог: каждая оценка объяснима и проверяема, работает на трёх языках, стоит $0 и не падает без интернета. Результаты DEV и контрольного набора в формате организаторов лежат в репозитории. Спасибо».

## Что делает решение особенным
1. **Два независимых метода.** Правила на RU/KZ/EN и LLM оценивают каждый критерий. Где они расходятся, система сама ставит флаг «нужна проверка человеком».
2. **Голосование модели.** LLM читает диалог 3 раза, и по каждому критерию берётся ответ большинства. Если прочтения расходятся, критерий уходит на проверку. Совпадение с ручной разметкой выросло с 78% до 82%, а разница итога с людьми сократилась с 15 до 10.6 балла.
3. **Математику считает код, а не модель.** Веса, перераспределение N/A, округление до 0.01 — детерминированный расчёт, совпадающий с расчётом во фронтенде.
4. **Каждый балл с доказательством.** Ссылка ведёт к точной реплике или к моменту в записи звонка. Для пропущенного действия указан участок, где оно ожидалось.
5. **Никогда не падает.** Нет ключа, перегружен Google, сработал фильтр модели — оценка переходит на правила, и диалог помечается.
6. **Настраивается без программиста.** Новый критерий или вес меняется в UI, создаётся новая версия чек-листа.
7. **Защита от подмены инструкций.** Текст диалога передаётся модели как данные, команды внутри чата («игнорируй правила») не выполняются.
8. **Готово к Dynamics 365.** Фронтенд собран как встраиваемый компонент (`frontend/d365/`).

## Ответы на вопросы жюри
| Вопрос | Ответ |
|---|---|
| Какая модель и сколько стоит? | Gemini Flash-Lite, бесплатный тариф, **$0**; 3 запроса на диалог (голосование). На платном Claude Sonnet 5.5 — расчёт ≈ $0.03–0.07 за оценку (`docs/demo/cost-report.md`). |
| Насколько точно? | Сверили с ручной разметкой QA на 11 трудных диалогах: в среднем 82% совпадений по критериям. Контакт и идентификация 100%, эмпатия 88%, грубые ошибки 82%, ведение и завершение 79%, консультация 73%, выявление потребности 55%. Слабые места мы знаем, и система отмечает их на проверку. |
| Почему не только LLM? | LLM иногда ошибается, отказывается отвечать или недоступна. Правила дают второе мнение и страховку, а расхождение двух методов — сигнал проверить вручную. |
| Как с казахским? | Оцениваем в оригинале, без перевода; правила содержат казахские словари. |
| Дикция, интонация? | Не оцениваем: работаем по транскрипту, звук не анализируем. Это честное ограничение, для него нужна обработка аудио. |
| Что если модель ошиблась? | Апелляция: проверяющий меняет оценку с причиной, итог пересчитывается, исходная оценка AI сохраняется. |
| Персональные данные? | Ключи и ссылки организаторов только в `.env`, в git их нет (проверено по всей истории). Данные организаторов в репозиторий не кладём. |
| Как проверяли? | 134 автотеста + 27 тестов QA, валидатор формата результатов, прогон UI в браузере, запуск из чистого клона по README. |
