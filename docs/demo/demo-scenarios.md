# Сценарии показа (реальные DEV-диалоги, rule-based режим)

Результаты ниже взяты из прогона текущего кода на DEV (копия БД). Данные организаторов уже обезличены (`[Имя скрыто]`). С ключом API цифры могут измениться: это отдельный прогон.

Подготовка:

```powershell
backend\.venv\Scripts\python -m uvicorn backend.app.main:app --port 8000
curl.exe -X POST "http://127.0.0.1:8000/ingest?group_id=DEV"
curl.exe -X POST http://127.0.0.1:8000/evaluate/batch -H "Content-Type: application/json" -d "{\"group_id\":\"DEV\",\"checklist_id\":\"cqa-default-v1\"}"
```

## A. Хорошо обработанный диалог с N/A — `p1-ru-013`

`GET /results/p1-ru-013` → **итог 100.0**, грубых ошибок нет, ручная проверка не нужна.

| Критерий | Ответ | Баллы / эффективный вес | Почему |
|---|---|---|---|
| C1 Контакт | Да | 15.38 / 15.38 | [03:30] оператор: «Здравствуйте! Я Кира. …» — поздоровалась и представилась в первом ответе |
| C2 Потребность | **N/A** | — | «Данных для ответа хватало с самого начала» — [00:00] клиент: «Где отчётность вашей компании посмотреть? Мне не выписка по счёту нужна.» |
| C3 Идентификация | **N/A** | — | Общий вопрос, данные счёта не раскрывались |
| C4 Консультация | 20 | 30.77 / 30.77 | Дан путь: «откройте Investors, затем Financial Information» |
| C5–C7 | Да / 10 / Да | 23.08 / 23.08 / 7.69 | Прощание: [04:36] «… Хорошего дня!» |

Что показать: два N/A с причиной; веса 15 + 20 ушли из знаменателя, остальные пересчитаны (C1 10 → 15.38, C4 20 → 30.77), максимум остаётся 100. Клик по evidence → `transcript[9]`.

## B. Серьёзное нарушение — `p1-ru-023`

`GET /results/p1-ru-023` → **итог 100.0, `critical_error: true`**, `review_criteria: ["C8"]`.

- C8 Грубые ошибки — **Да**: «Выявлено: услуга в обход компании. Основание — [03:03] оператор: «Можете дать личный номер? Вечером созвонюсь с вами и за плату объясню, какие бумаги взять. Это будет моя частная консультация.»»
- По PDF грубая ошибка не снимает баллы, а «отмечается отдельно», поэтому итог 100 и красный флаг одновременно. Флаг всегда уходит человеку (`critical_flag`): ложное обвинение оператора так же дорого, как пропуск.
- Тот же тип нарушения находится на KZ (`p1-kz-013`) и EN (`p1-en-013`).

## C. Система не уверена и отдаёт решение человеку — замена критерия

Проверка организаторов на t+23h: «заменить один критерий». Сохраняем [checklist_v2_example.json](checklist_v2_example.json) (станет `cqa-default-v2`), где C7 «Завершение» заменён на C9 «Предупреждение об ожидании» (binary, вес 5, N/A — «пауз не было»):

```powershell
curl.exe -X POST http://127.0.0.1:8000/checklists -H "Content-Type: application/json" --data-binary "@docs/demo/checklist_v2_example.json"
curl.exe -X POST http://127.0.0.1:8000/evaluate -H "Content-Type: application/json" -d "{\"conversation_id\":\"p1-ru-013\",\"checklist_id\":\"cqa-default-v2\"}"
```

Что происходит (измерено):

| Режим | C9 | Итог | Ручная проверка |
|---|---|---|---|
| Без ключа, критерий без `keywords` (удалить поле из файла) | N/A: «Rule-based режим: для нового критерия нет правил/ключевых слов, нужна оценка LLM или проверяющего» | 100.0 | **да** (`no_rule`) — система не делает вид, что знает ответ |
| Без ключа, `keywords: ["минут","подождите","please wait","күте тұрыңыз"]` | Нет | 92.31 | нет |
| С Claude | оценка по `description` из JSON, без правки кода; платный только 1 вызов на диалог (остальные 7 критериев из кэша ответов) | — | если правила и модель разошлись |

В гибридном режиме этот же механизм ловит спорные критерии старого чек-листа: `rules_llm_disagree`, `llm_low_confidence`, `llm_fallback`. Очередь — `GET /results?needs_review=true`, решение — `POST /results/{id}/review`; флаг снимается, итог пересчитывается, исходная оценка остаётся в `original`.

## D. Звонок: переход к фрагменту записи — `p4-ru-001`

`GET /results/p4-ru-001` → итог **81.33**.

- C1 Да — evidence `[2026-11-03T13:11:17…]` оператор: «… меня зовут [Имя скрыто] Здравствуйте, чем могу вам помочь.», `offset_sec: 76.62`.
- C4 15 — основной вопрос решён, но клиент уточнял, `offset_sec: 312.89`.
- C7 **N/A** — [13:15:20] система: «Клиент завершил разговор.» — завершать было некому.
- Плеер: `<audio src="http://127.0.0.1:8000/conversations/p4-ru-001/audio/stream#t=76.62">` — сервер отдаёт свежую mp3-ссылку (ссылка организаторов живёт ~1 ч).

## E. Апелляция и пересчёт

```powershell
curl.exe -X POST http://127.0.0.1:8000/results/<result_id>/appeals -H "Content-Type: application/json" -d "{\"criterion_id\":\"C2\",\"comment\":\"Клиент сам всё описал, уточнять было нечего\"}"
curl.exe "http://127.0.0.1:8000/appeals?status=open"
curl.exe -X POST http://127.0.0.1:8000/results/<result_id>/review -H "Content-Type: application/json" -d "{\"criterion_id\":\"C2\",\"decision\":\"change\",\"new_value\":\"NA\",\"reason\":\"Данных хватало с начала\"}"
```

Хороший кандидат — `p1-ru-005`: правила поставили C2 «Нет», а в разметке N/A (это реальный промах, см. [evaluation.md](evaluation.md)). В ответе на review: `overall_before` → `overall_after`, `original` не меняется.
