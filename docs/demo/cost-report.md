# Стоимость оценки

**Gemini измерен вживую 2026-11-08** (таблица «Факт» внизу). Claude Sonnet 5.5 не вызывался: для него стоимость расчётная, по методике ниже.

## Бесплатный режим (Gemini через OpenAI-совместимый API)

ТЗ разрешает «локальную модель, бесплатный или платный API»; название и стоимость обязательны только для платной.
Поэтому основной демо-режим может работать бесплатно, а Claude Sonnet 5.5 — указан как платная опция с расчётной стоимостью.

| Режим | Стоимость оценки | Ограничения |
|---|---|---|
| Gemini Flash, бесплатный ключ AI Studio, `LLM_STRATEGY=single_call` | **$0** | лимиты запросов в минуту/день (точные — в консоли AI Studio); на бесплатном тарифе Google может использовать данные для улучшения сервисов — проверить условия; качество на KZ не измерено |
| Claude Sonnet 5.5 | ≈ $0.03–0.07 (расчёт) | нужен баланс в console.anthropic.com |
| Rule-based | $0 | нет второго мнения для ручной проверки |

Как бесплатный режим укладывается в лимиты: 1 запрос на диалог (`single_call`), пауза между запросами (`OPENAI_COMPAT_MIN_INTERVAL_SEC=4`),
повтор с ожиданием на 429, кэш ответов (повторно один и тот же диалог не запрашивается), при сбое — ответ правил по критерию и флаг проверки.

## Оценка на один диалог (`LLM_EFFORT=low`)

Допущения: ~3 символа на токен для смеси RU/KZ/EN → префикс ≈ 1.4 тыс. токенов, критерий ≈ 150 токенов; выход (размышление + JSON) 300–800 токенов на вызов при `per_criterion`, 1.5–3 тыс. на весь `single_call`.

| Модель / стратегия | Вызовов | Вход | Выход | Итого ≈ |
|---|---|---|---|---|
| **Sonnet 5.5, `per_criterion` (по умолчанию)** | 8 | 1 запись префикса + 7 чтений + 8 × критерий ≈ $0.008 | 2.4–6.4 тыс. ток. ≈ $0.024–0.064 | **$0.03–0.07** |
| Sonnet 5.5, `single_call` | 1 | префикс + 8 критериев ≈ $0.005 | 1.5–3 тыс. ток. ≈ $0.015–0.03 | **$0.02–0.035** |
| Opus 5.5, `per_criterion` | 8 | ≈ $0.015 | ≈ $0.05–0.13 | $0.06–0.14 |
| Opus 5.5, `single_call` | 1 | ≈ $0.011 | ≈ $0.03–0.06 | $0.04–0.07 |
| Rule-based | 0 | 0 | 0 | 0 |

Весь DEV (65 диалогов) на Sonnet 5.5: ≈ $2–4.5 (`per_criterion`) или ≈ $1.3–2.3 (`single_call`). Модель переключается через `LLM_MODEL` + `LLM_PRICE_*` в `backend/.env` без правки кода; кэш ответов привязан к модели, поэтому ответы разных моделей не смешиваются.

**Главный вывод:** 80–90% стоимости — выходные токены. Кэш делает вход почти бесплатным, поэтому экономить нужно на выходе (effort, длина объяснения, число вызовов), а не на входе.

## Что уже снижает стоимость без потери качества

| Механизм | Эффект |
|---|---|
| Кэш префикса (`cache_control` на транскрипте) | Вызовы 2–8 читают транскрипт по $0.20 вместо $4 за 1M |
| Кэш ответов (`LLM_RESULT_CACHE=1`) | Повторная оценка того же диалога — $0. Замена одного критерия чек-листа — 1 вызов вместо 8 (проверено тестом) |
| `LLM_EFFORT=low` | Меньше размышлений на простых бинарных критериях |
| Идемпотентный batch + защита от дубликата | Уже оценённые диалоги не оплачиваются второй раз; двойной клик не запускает второй прогон |
| Fallback на правила | Сбой API не требует повторной платной оценки всего диалога |

## Выбор конфигурации — по замеру, а не наугад

`single_call` и Haiku дешевле, но влияние на качество не измерено. Порядок (стоит центы):

1. `python -m ml.live_smoke` — фактическая стоимость и токены одного диалога.
2. `LLM_STRATEGY=per_criterion` и `single_call` → `python -m eval.run_eval --modes hybrid` для каждой; сравнить accuracy, false PASS по C8 и `$/диалог`.
3. Выбрать самую дешёвую конфигурацию без потери в accuracy и в false PASS по грубым ошибкам; вписать факт в эту таблицу и в `backend/README.md`.
