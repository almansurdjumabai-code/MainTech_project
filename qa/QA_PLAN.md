# QA-план CQA

Состав папки `qa/`:

| Файл | Зачем |
|---|---|
| `scoring.reference.mjs` | Эталонный расчёт итога по чек-листу (стр. 2 «Порядок расчёта»). |
| `scoring.test.mjs` | 27 тестов движка. `node --test "qa/*.test.mjs"`; для движка команды — `CQA_ENGINE=путь node --test "qa/*.test.mjs"`. |
| `manual_labels.csv` | Ручная разметка 11 диалогов (колонки `model_*` заполнить после прогона модели). |
| `gold_labels.json` | Та же разметка с обоснованием и номерами реплик-доказательств. |
| `validate_results.mjs` | Проверка `results/*/results.json` перед push: формат 1.0, все 8 критериев, допустимые значения, пересчёт `final_score`, `critical_flag`, дубли и пропуски ID, номера реплик с 1. |
| `compare.mjs` | Сравнение с моделью: совпадение по критериям, разница итога, список расхождений для ML. |

## 1. Тесты движка скоринга — что проверяется

| Случай | Ожидаемо |
|---|---|
| Все «да», шкалы на верхней ступени | 100 |
| Всё «нет» / нижние ступени | 0 (не `null`) |
| N/A у идентификации (вес 20) | Остальные веса ×1.25; итог 100 при остальных «да» |
| N/A у идентификации + «нет» за контакт | 87.5 |
| N/A у потребности + «нет» за контакт | 75/85 → **88.24** (округление) |
| N/A у завершения + ведение = 7 | 90.5/95 → **95.26** |
| Консультация 0/5/10/15/20 | 80/85/90/95/100 |
| Ведение 0/4/7/10 | 0/6/10.5/15 баллов → 85/91/95.5/100 |
| Значение вне шкалы (12, 5) | Ошибка валидации |
| N/A у c01 или c06 | Ошибка: N/A там не разрешён |
| Все применимые N/A (кастомный чек-лист) | Итог **не считается** (`null`, не 0, не NaN) |
| Грубая ошибка | Флаг `gross=true`, итог не меняется |
| Замена критерия | Новый вес и шкала применяются, итог пересчитан |

Важно: в базовом чек-листе «все N/A» невозможно (у c01, c05, c06 N/A запрещён), поэтому тест использует изменённый чек-лист. В UI проверьте, что при итоге `null` отображается «не рассчитывается», а не `0` или `NaN`.

Типичные баги, которые ловят эти тесты: N/A считается как 0; шкала 0–10 с весом 15 даёт 10 вместо 15; округление каждого критерия отдельно и потом суммирование (итог «уплывает» на 0.01); `toFixed` на float.

- Нет представления в первом ответе: `p1-en-015`, `p1-ru-014` («Привет»), `p1-kz-008` («Сәлем»).
- Реплики бота с приветствием стоят **до** оператора. Модель не должна засчитывать их как приветствие оператора.
- Во всех чатах первые реплики `[1]–[7]` — бот и эскалация. Индексы реплик в ссылках-доказательствах считаются от начала массива `transcript`, включая бота.
- В звонках есть дубли реплик (в `p4-ru-001` реплики 19 и 20 совпадают), артефакты распознавания и `[Имя скрыто]`. Представление с `[Имя скрыто]` засчитываем.
- В `audio_url` тоже есть `sig=`, поэтому сами данные в репозиторий не кладём.

Спорные решения (`disputed` в JSON), их нужно согласовать с командой до правки промптов:
1. Раскрытие ограничения на счёте без идентификации: «Нет» по c03 **и** грубая ошибка c08 (`p1-ru-009`, `p1-kz-015`)? Я поставил «да», потому что информация о счёте конфиденциальна.
2. Клиент ушёл после «С чем помочь?»: c02 «Да» или N/A? Условие N/A формально не выполнено, поэтому поставил «Да».
3. В звонке `p4-ru-001` границы между c05 и c06 размыты.

Как было запланировано:

1. Выбрать 10 диалогов: 4 RU (в т.ч. 1 звонок), 3 KZ, 3 EN (в т.ч. 1 звонок). Брать специально «трудные»: с идентификацией, обрывом чата, недовольным клиентом.
2. Два человека независимо размечают по чек-листу в `manual_labels.csv`, без подглядывания в ответ модели. Спорные — обсудить и записать итоговое решение.
3. Прогнать модель, заполнить колонки `model_*`, в `diff_criteria` перечислить критерии с расхождением.
4. Передать ML таблицу расхождений: критерий → ID диалога → номер реплики → «модель сказала X, по чек-листу Y, потому что…».

Метрики для питча: доля совпадений по каждому критерию и средняя разница итога.

## 3. Граничные случаи (проверить на модели)

| Ситуация | Правильно |
|---|---|
| Общий вопрос о тарифах, данные клиента не раскрываются | Идентификация **N/A** |
| Смена номера / вывод средств / баланс без проверки личности | Идентификация **Нет** |
| Проверка личности после раскрытия данных | **Нет** (должна быть *до*) |
| Чат оборвался (клиент ушёл, таймаут) до завершения | Завершение **N/A** |
| Оператор сам закрыл чат без прощания | Завершение **Нет** |
| Клиент ушёл до формулировки запроса | Консультация **N/A** |
| Клиент сразу дал все данные | Выявление потребности **N/A** |
| «Переведите мне лично, я вложу» / «дайте личный номер, проконсультирую платно» | Грубая ошибка **Да**, даже если клиент отказался |
| Приветствие не на языке клиента (клиент пишет на KZ, оператор на RU) | Контакт **Нет** |
| Реплики бота поздоровались, оператор — нет | Контакт **Нет** (бот — только контекст) |
| Клиент недоволен, оператор вежлив, но проблему проигнорировал | Эмпатия **Нет** |
| Долгое ожидание без предупреждения | Ведение ≤ 7 |

Для каждого: у пропущенного действия должна быть ссылка на место, где оно ожидалось; у N/A — объяснение условия.

## 4. Сквозные сценарии продукта

1. **Оценка**: загрузить диалог → выбрать чек-лист → оценить. Есть ответ, баллы, вес, объяснение и реплика по каждому критерию, итог и секции.
2. **Ссылка на реплику**: клик по доказательству → прокрутка и подсветка нужного сообщения; для звонка — плеер перематывает на момент (ISO-время → секунды от начала).
3. **Апелляция**: выбрать критерий, комментарий, сохранить. Перезагрузить страницу — апелляция на месте.
4. **Решение**: проверяющий видит спорную оценку, комментарий и фрагмент; меняет оценку с причиной. Итог пересчитан. В карточке видны исходная оценка, решение и финальный итог.
5. **Подтверждение**: проверяющий подтверждает — итог не меняется, статус «рассмотрено».
6. **Замена критерия**: изменить критерий в UI → сохранить → применить к диалогам → итоги пересчитаны, старые результаты не сломались.
7. **Негатив**: пустой транскрипт, диалог только с ботом, очень длинный звонок, ошибка API модели (показать понятное сообщение, а не белый экран), CORS (данные идут через бэкенд).

| 1:00–3:00 | Запускаем оценку (или открываем заранее посчитанную). Проходим по 2–3 критериям: объяснение + клик → подсветка реплики. Показываем **N/A** с причиной и как изменились веса. Итог и секции. Отдельно — диалог с **грубой ошибкой**: флаг, баллы не тронуты. | |
