# Стоимость оценки

**Фактическая стоимость ещё не измерена — живого вызова API не было (нет ключа).** Ниже — расчётная оценка с явной методикой. После `python -m ml.live_smoke` таблица «факт» заполняется из `pipeline.cost_usd` (считается по `usage` ответа API).

| Модель | Вход | Выход | Запись кэша (5 мин) | Чтение кэша |

## Оценка на один диалог (Opus 5.5, `LLM_EFFORT=low`)

Допущения: ~3 символа на токен для смеси RU/KZ/EN → префикс ≈ 1.4 тыс. токенов, критерий ≈ 150 токенов; выход (размышление + JSON) 300–800 токенов на вызов при `per_criterion`, 1.5–3 тыс. на весь `single_call`.

| Стратегия | Вызовов | Вход | Выход | Итого ≈ |
|---|---|---|---|---|
| `per_criterion` (по умолчанию) | 8 | 1 запись префикса + 7 чтений + 8 × критерий ≈ $0.015 | 2.4–6.4 тыс. ток. ≈ $0.05–0.13 | **$0.06–0.14** |
| `single_call` | 1 | префикс + 8 критериев ≈ $0.011 | 1.5–3 тыс. ток. ≈ $0.03–0.06 | **$0.04–0.07** |
| `per_criterion` на Haiku 5.5 | 8 | — | — | ≈ $0.002–0.004 |
| Rule-based | 0 | 0 | 0 | 0 |

Весь DEV (65 диалогов) на Opus 5.5: ≈ $4–9 (`per_criterion`) или ≈ $2.5–4.5 (`single_call`).

**Главный вывод:** 80–90% стоимости — выходные токены. Кэш делает вход почти бесплатным, поэтому экономить нужно на выходе (effort, длина объяснения, число вызовов), а не на входе.

## Что уже снижает стоимость без потери качества

| Механизм | Эффект |
|---|---|
| Кэш префикса (`cache_control` на транскрипте) | Вызовы 2–8 читают транскрипт по $0.20 вместо $4 за 1M |
| Кэш ответов (`LLM_RESULT_CACHE=1`) | Повторная оценка того же диалога — $0. Замена одного критерия чек-листа — 1 вызов вместо 8 (проверено тестом) |
| `LLM_EFFORT=low` | Меньше размышлений на простых бинарных критериях |
| Идемпотентный batch + защита от дубликата | Уже оценённые диалоги не оплачиваются второй раз; двойной клик не запускает второй прогон |
| Fallback на правила | Сбой API не требует повторной платной оценки всего диалога |
